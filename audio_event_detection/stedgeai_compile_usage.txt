Run from Windows Command Prompt:

  stedgeai_compile.bat "MODEL_FOLDER_OR_EXPERIMENT_NAME" "C:\path\board.mpool"

Example (from this script's directory):

  stedgeai_compile.bat "bcresnet_tf_v06_2026_10_22_08_41_42_batchsize_400_hinoise" "..\application_code\audio\STM32N6\Projects\X-CUBE-AI\models\stm32n6.mpool"

An experiment name is resolved under tf\src\experiments_outputs beside this
script. A folder path is resolved relative to the current working directory.
The memory-pool path is relative to the current working directory or absolute.
Both quantize_model.tflite and quantized_model.tflite are accepted recursively;
multiple matches cause an error instead of selecting a model arbitrarily.

Optional executable override:

  stedgeai_compile.bat "MODEL_FOLDER" "BOARD.mpool" -StEdgeAi "C:\ST\STEdgeAI\4.0\Utilities\windows\stedgeai.exe"

Requires a full Windows STEdgeAI installation (default: C:\ST\STEdgeAI\4.0).
Targets STM32N6, ST-AI C API, Neural-ART optimization level 3, with cache
maintenance and native-float software fallback. Neural-ART generates per-pool
binary weights automatically; the generic --binary switch is unsupported.

Each invocation creates NeuralART_compilation_TIMESTAMP under the model folder.
Successful output contains generated/, workspace/, Middlewares/ST/AI/, the
copied memory pool, compiler profile, log, command.json, weights_manifest.txt,
and INTEGRATION.txt. Existing runs are preserved. Failures return a nonzero
exit code and retain diagnostics; a failed output is not an integration package.

generated/audio_model_weights.h and audio_model_weights.c are generated beside
the model sources. Copy the header to your audio include folder and compile
the C file in your project whenever replacing the model.
The C file contains the section table, sources[] array and copy/CRC functions.
SRAM source defaults are 0x70400000 for the first initializer and 0x70480000
for the second, ordered by ascending SRAM destination address (512 KiB slots).
Program the listed binaries at those flash addresses. SOURCE_ADDRESS macros
can still be overridden in the C file or build flags. Flash-only needs no copy.
Call AudioModelWeights_Init() once after enabling memories and before model
initialization/inference; it copies all SRAM initializers and verifies all CRCs.
It records the weight pool's address from the supplied .mpool, the complete
binary length, and CRC32 compatible with AudioRuntime_VerifyWeights().
This header supports one flash initializer and up to two writable SRAM
initializers, each with an absolute byte address. Section order is ascending
destination address, documented by numbered macros and binary-name comments.
CopyAll() uses generated sources[], copies SRAM initializers, cleans CPU cache and verifies
all section CRCs. For flash sections supply {NULL, 0}; program them in place.
Verify() checks every destination section. Init(), CopyAll() and Verify() use
the same API for one or multiple sections; there is no single-section copy helper.
The original single-range macros remain available for single-section models.
The batch wrapper requires stedgeai_weights_header.ps1 beside the main script.
For SRAM weights, firmware must copy the initializer from persistent storage
to the generated SRAM address before CRC verification and model initialization.
Verify before inference if the initializer includes mutable activation data.

The memory pool must match the board's available memory and linker layout.
The supplied project pool may be too small for larger models. ST's reference
pool uses external RAM and flash; use it only when those regions are available
and configured on the board. Compilation does not establish hardware validity.
